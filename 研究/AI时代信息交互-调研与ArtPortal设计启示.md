# AI 时代信息交互范式:调研与 ArtPortal 设计启示

> 路线图第 21 项(用户 2026-07-20 指定)。方法:5 路并行联网调研 → 抓 22 个源 → 提 96 条声明 → 每条 3 票对抗核实(需 2/3 反驳才淘汰)→ 综合。25 条核验,**23 条确认、2 条证伪**。置信度、局限、来源均如实标注。
> 用途:作为第 19 项(界面继续优化,v0.76.0 起)、第 20 项(地球仪主界面,v0.77.0)的交互设计依据。
> 全程简体中文。

---

## 0. 一句话结论

信息交互正从 Web2.0 的**「用户驱动」**范式(搜索框 + 无限信息流 Feed + App 多层导航 + 红点通知)转向 AI 时代的**「代理式 / 生成式 + 意图导向」**范式:用户声明**意图**,系统主动规划、聚合、并按意图**即时生成任务专属界面**。但新范式也带来**新失败模式**(纯对话式在探索型任务上低效;AI 引用"看似可信实不可溯源")。对 ArtPortal,这套研究给出一个清晰判断:**地球仪主界面技术上成熟可行、方向正确,但"以地球仪为主界面"从无成功先例——应把它做成"地点锚定的发现层",与现有列表/筛选/标签体系共存、可一键互切、可降级,并用真实 A/B 数据决定它能否"转正"为默认入口。** 我们的反幻觉红线,恰好是 AI 时代最稀缺的竞争力。

## 1. 核心范式跃迁(Web2.0 → AI 时代)

| 维度 | 上一代(Web2.0 / 移动互联网) | AI 时代新范式 | 依据(置信度) |
|---|---|---|---|
| 发起方式 | 用户亲自搜索 / 导航 / 决策 | **意图导向**:声明想要的结果,系统规划执行(代理式 / Agentic Web,人-AI 沿"被动→辅助→轮次→并行协作"光谱) | 高(arXiv 2507.21206、2410.22370) |
| 界面形态 | 单一固定信息架构,人去适配 | **生成式 UI**:按意图即时生成任务专属界面(对话式/画布式/情境式/模块式/模拟 五类) | 高(arXiv 2508.19227、2410.22370) |
| 信息组织 | 列表 + 无限信息流 | 多形态,含**空间/地图/地球仪**式地点锚定探索(技术成熟逾十年) | 高(Globe.GL、deck.gl、Google WebGL Globe 2011) |
| 触达节奏 | 红点 + 即时推送(永远在线) | **择机批量送达**:推迟到自然"断点"递送,降低心智负荷 | 高(ACM IMWUT 2018) |
| 可信度 | 蓝色链接 = 可点击核验 | AI 摘要**抑制**查证(答案引擎下平均只查 2 源 vs 传统 12 源),"有引用 ≠ 可溯源" | 高(FAccT 2025) |
| 个性化 | 协同过滤 → 过滤气泡 | 反馈回路制造同质化;**serendipity + 算法可供性**主动破泡 | 高(arXiv 2502.13539、JASIST 2025) |

**两个被证伪的流行说法(别踩)**:
- ❌「AI 会把人从交互中彻底解放、变成机器对机器」——0/3 通过。人在环仍是刚需,尤其反幻觉产品。
- ❌「生成式 UI 用户偏好比聊天高 72%」——0/3 通过。生成式 UI 是**方向**,不是"必然更优",别拿它当营销话术。

## 2. 五条经核验的设计原则(高效 × 人性化)

1. **意图直达 + 任务专属界面(效率)**。探索艺术机会属"高信息密度、多轮、探索型"任务——**恰恰是纯对话式聊天的失败区**。别把 ArtPortal 做成"一个聊天框问答";要让用户以意图驱动、但落到可扫视、可对比、可深读的**结构化界面**(地球/列表/详情面板)。
2. **择机批量、无红点成瘾(人性化 / calm technology)**。旧范式实测危害:普通用户约 100 条通知/天,降绩效、增错误、诱压力、致卸载。ArtPortal 的周刊/站内通知**继续走"每周固定送达 + 批量"**(我们已经是这样,守住),绝不加"未读红点轰炸 + 即时打断"。
3. **为不完美设计:让不确定性与来源可见(反幻觉可信)**。这是 AI 时代最硬的一条,也正中我们红线。研究实证:AI 答案引擎引文准确率仅 49–68%、23–32% 陈述无来源支撑,且"有引用"会制造**虚假可信**。ArtPortal 的对策必须是**真可溯源**:每条机会一键回机构官网原文;"AI 检索/机翻/用户投稿"来源如实标注;关键字段逐字 evidence(我们已有程序校验)——**把"支撑某字段的原文原句"暴露到界面**,而不是只贴个 URL。
4. **serendipity + 可见的筛选可供性(反过滤气泡)**。纯精准推荐会同质化、降满意度。对策:在个性化里注入**意外但相关**的机会(跨门类/跨地域),并给用户**可见的**门类/地域/时间筛选开关 + "为何推荐"的透明说明。注意局限:透明干预对"算法素养低"的用户效果打折——所以说明要**朴素直白**,不能只给技术标签。
5. **移动 / 微信优先、可降级、弱网可用**。我们主力场景就是手机+微信,任何炫技(尤其地球仪)都必须有**等价的降级路径**,首屏不被 3D 加载阻塞。

## 3. ArtPortal 应主动采纳的范式清单(A)

1. **把"搜索框"升级为代理式意图检索**:用户表达需求 → 代理跨一手源自动核实、聚合、编排(周刊已是雏形)——**但保留人在环 + 可退回的确定性列表**(遇到无来源/幻觉时优雅降级到列表,绝不硬编)。
2. **用"生成式/情境式 UI"替代纯固定架构与纯聊天**:地球仪 + 按意图即时生成的筛选/详情面板,就是"情境式 UI"的落地。
3. **"择机批量送达"替代红点即时打断**:守住现有周刊/通知节奏。
4. **让不确定性与来源可见**:来源徽章、一键回官网原文、evidence 原句可查、AI/机翻/投稿标注——把反幻觉红线**做成可见的信任界面**,这是我们相对通用 AI 产品的差异化护城河。
5. **个性化内建 serendipity + 可见筛选可供性 + 算法透明**。

## 4. 地球仪主界面 + 机会发现:具体设计(C)——旗舰改版 v0.77.0

> 技术结论(高置信):Globe.GL(ThreeJS/WebGL,原生 lat/lng 映射、Hex Bins 六棱柱聚合、Heatmap 高斯核密度)/ deck.gl(GPU 大规模)/ Google WebGL Globe(2011 开源)——**渲染技术成熟,数千点高帧可行**。
> 诚实警示(caveat):**至今无主流信息产品以地球仪为"主界面";桌面 demo ≠ 移动/微信/国内弱网实测;真实"机会卡片"(而非光点)的信息密度是更难的问题。** 所以下面是"如何低风险地做对",不是"直接全量替换"。

**定位:地球仪是"发现层/入口",不是列表的替代。** 地球负责"从地点出发的探索与 serendipity",列表负责"高密度扫视与对比深读",两者一键互切。

**4.1 信息密度与聚合**
- 缩放自适应:**远看**用 Hex Bins/Heatmap 呈现"密度热区"(北京/上海/伦敦/纽约汇聚 N 个机会),**近看**散开成单点/小卡。避免标签重叠与"满屏麻点"。
- 海量点:GPU 图层 + 聚类降点;点只承载"身份"(标题/机构/门类色),详情走面板,别把整张卡片糊到球上。
- 复用现有**门类彩色标签体系**做球面图层配色/过滤(23 门类色系已有)。

**4.2 地点锚定浏览**
- 机会按**机构经纬度**锚定球面;点击某地 → 弹出**情境式面板**列出该地机会(可继续筛选)。支持"以地点为起点"的探索(旅行/驻留场景天然契合)。
- **前置依赖**:机会数据需补 `lat/lng`。**反幻觉注意**——坐标可由 `city_zh/country_zh` 地理编码推导,但**必须如实标注粒度**(城市级中心点 ≠ 精确地址);坐标是"位置提示"不是"经核实的地址事实",别让地球制造精确的假象。

**4.3 与现有体系共存(关键)**
- **地球 ⇄ 列表 一键切换**;筛选(三频道/门类标签/时间范围)**同时作用两个视图**,状态共享。
- 门类标签行 = 球面图层过滤器;搜索/AI 检索结果可在球上高亮落点。
- **移动端默认列表**、地球作为"可选发现层"入口(先不赌手机首屏直接上 3D)。

**4.4 性能与国内可加载**
- 静态资源(库/纹理/瓦片)走**国内 CDN + 本地自托管**(延续我们"封面存自己服务器"的做法,不依赖被墙外链);按需加载、聚类降点。
- 低端 GPU/移动有 draw-call/内存瓶颈 → 设**降级阈值**(点数超限自动切聚合/切列表)。

**4.5 可访问性与降级**
- 无 WebGL/弱设备/读屏用户 → **等价的列表 / 2D 地图降级路径**;球面元素有文本替代;键盘可达;**首屏不阻塞在 3D 加载**(先出列表,地球异步加载)。

**4.6 低风险落地路线(建议)**
1. **v0.77.0-a**:先做数据侧——给机会补 `lat/lng`(城市级,粒度标注),不动主界面。
2. **v0.77.0-b**:地球作为**新增 tab/入口**(非默认),桌面先行,列表保持默认。
3. **v0.77.0-c**:小流量 A/B——测发现转化率、首屏性能、移动/微信可用性;达标才考虑"转正"为默认入口。**用数据决定,不用炫技决定。**

## 5. 界面继续优化的即时清单(喂 v0.76.0 起滚动)

不必等地球仪,这些"高效 + 人性化"原则现在就能落:
- **信任界面**:详情页把"支撑关键字段的原文原句(evidence)"做成可展开查看,而非只有来源链接;来源类型徽章(官网直采/AI 检索/机翻/用户投稿)统一、显眼、诚实。
- **渐进披露 + 信息密度分层**:卡片只放决策必需(标题/机构/门类/截止/地点),细节进详情,降认知负荷。
- **serendipity 入口**:收藏夹/主页加"意外发现"(跨门类/跨地域的相关机会)+ 朴素的"为什么推荐你看"。
- **calm**:守住无红点轰炸;通知批量择机。
- **移动/微信**:持续弱网、降级、可访问性打磨。

## 6. 诚实的风险与开放问题(不可回避)

- **地球仪"主界面"无先例**:移动/微信弱网真实可用性、首屏性能、发现转化率均需**自行 A/B 实测**并设降级阈值。别把它当"一定成功"的赌注。
- **代理式检索 × 反幻觉如何协同**:代理自动跨源聚合与"关键字段逐字 evidence 是原文子串"的程序校验怎么配合?遇到幻觉/无来源如何优雅降级到确定性列表?(这正是我们比通用 AI 产品的优势所在,要设计好)
- **serendipity × 精准筛选如何平衡**:既破同质化又不稀释相关性,针对艺术机会用户群尚无实证参数,需自建指标。
- **生成式 UI 在强反幻觉约束下的边界**:即时生成界面是否会引入不可溯源的呈现?生成层须强制来源锚定与可核验。
- **证据分层**:范式框架(Agentic Web / 生成式 UI)多为 arXiv 预印本 + 部分 aspirational(存在 hype 质疑:Gartner 预测约 40% 代理项目取消);更硬的同行评审证据在"通知危害/答案引擎不可溯源/算法可供性/CHI 设计原则"。**做方向参考,不做既成事实。**
